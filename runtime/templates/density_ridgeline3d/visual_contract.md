# 三维双轮廓密度曲线与基线焦点视觉合同

- X 轴使用源表 `Density X`，Y 轴使用真实且带单位的 `Condition Position`，Z 轴使用上游提供的
  两列同单位 `Density`。两列密度表头都必须明确 `Density/密度` 且规范化单位一致；Z 轴标题冻结为
  `Density (<共同单位>)`，两列均明确无量纲时冻结为 `Density (dimensionless)`。
- 每个条件使用一种克制的定性颜色；该条件同行提供的 `Solid Density` 与 `Dashed Density` 共用颜色，
  并分别固定为实线与虚线。颜色只编码 Condition ID，线型只编码两列密度角色。
- 轮廓曲线不显示逐点符号或下垂线。每个条件只在 Z=0 基线显示一个暖色焦点符号，并以源表
  `Focal X` 值作为可编辑标签；不得把焦点提升到曲线上或从曲线反推高度。
- 图例只解释“实线轮廓、虚线轮廓、基线焦点”三种语义，使用无边框可编辑对象；条件数值已经由
  Y 轴编码，不再建立冗余的条件图例。
- 白色背景、Arial、克制色族；禁止彩虹色、填充墙、阴影、Waterfall、装饰性第三轴和密集网格。
- 条件颜色数量按 2–6 组适配；页面、相机、轴标题、刻度、线宽、焦点尺寸与标签字号使用本路线
  已验证的固定视觉 profile，并在 Origin 对象中反读。不得直接照搬参考位图的像素大小。
- 正式成功必须同时具备可编辑 OPJU、PNG/PDF/TIF、三轴/相机/XYZ 映射/线型/线宽/颜色、焦点
  连接状态/尺寸/标签、图例反读，以及与导出哈希绑定的人工视觉检查。焦点 marker 的具体 shape
  不写入、不反读，也不属于兼容性承诺。

本合同已经在真实 Origin 2024b / 10.15 隔离实例中通过 OPJU、PNG/PDF/TIF、对象反读与人工
视觉检查。后续主机仍须通过实时 smoke 与 `OPEN_GL_3D` 能力检查，不能只凭安装版本推定可用。
